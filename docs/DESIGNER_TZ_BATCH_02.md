# DESIGNER_TZ_BATCH_02 — foreground scene rebuild

## Задача

Текущая интеграция механически работает, но визуально не соответствует утверждённому концепту. Нужно не «украсить UI», а пересобрать ключевые production-ассеты так, чтобы экран снова воспринимался как живая сцена склада/магазина, а не как интерфейс с маленьким персонажем.

Главный ориентир по композиции:
- персонаж — заметный foreground-объект, не маленькая фигурка;
- тележка — настоящая игровая корзина и второй главный foreground-объект;
- стеллажи — крупные, близкие, с глубиной, занимают центр сцены;
- игрок должен ощущать, что находится перед полками, а не смотрит на далёкие узкие шкафы;
- UI остаётся поверх сцены и не должен визуально конкурировать с игровым миром.

Не переделывать уже принятые товарные иконки Batch 01 без отдельной причины.

---

## 1. Персонаж — ПЕРЕРИСОВАТЬ ПОЛНОСТЬЮ

Текущий персонаж слишком маленький и по масштабу выглядит как декоративная фигурка. Нужен герой, который в игре занимает примерно 18–22% высоты игрового canvas 1600×900.

### Стиль
- casual 2D / clean pixel-inspired art;
- крупный читаемый силуэт;
- красная рабочая форма/кепка сохраняются;
- без фотореализма;
- без лишних мелких деталей;
- лицо и руки должны читаться на игровом масштабе;
- пропорции ближе к утверждённому концепту: крупная голова, компактное тело, заметные руки и ноги.

### Production format
Создать отдельные PNG-кадры с прозрачным фоном. Не sprite-sheet: отдельные файлы проще проверять и менять.

Базовый canvas каждого кадра: **320×420 px**, transparent.

Нужны:

`assets/character-v2/idle-01.png`
`assets/character-v2/idle-02.png`
- 2 кадра лёгкого idle;

`assets/character-v2/walk-01.png`
`assets/character-v2/walk-02.png`
`assets/character-v2/walk-03.png`
`assets/character-v2/walk-04.png`
- 4 кадра ходьбы вправо;
- левое направление будет зеркалиться кодом;

`assets/character-v2/pick-01.png`
`assets/character-v2/pick-02.png`
`assets/character-v2/pick-03.png`
- взять товар с полки / потянуться рукой;

`assets/character-v2/cart-01.png`
`assets/character-v2/cart-02.png`
- руки на ручке тележки / короткое состояние после добавления товара.

Критично: стопы персонажа должны стоять примерно на одной baseline во всех кадрах. Нельзя прыгать по X/Y между состояниями.

## 2. Тележка — ПЕРЕРИСОВАТЬ

Текущая тележка слишком маленькая, тонкая и визуально не держит роль основной корзины.

Нужна тележка как второй главный объект foreground.

Файл:
`assets/character-v2/cart-large.png`

Размер canvas: **520×360 px**, transparent.

Требования:
- перспектива 3/4, как в утверждённом концепте;
- крупные колёса;
- массивная ручка;
- корзина достаточно глубокая, чтобы внутрь можно было программно накладывать 4–8 иконок товаров;
- область внутренней корзины должна быть визуально свободной;
- нельзя рисовать фиксированные товары внутрь;
- сетка корзины не должна быть слишком плотной, иначе наши product sprites пропадут;
- тележка должна выглядеть пропорционально персонажу высотой ~260–320 px в игре.

Дополнительно:
`assets/character-v2/cart-shadow.png`
- мягкая овальная тень;
- **520×120 px**, transparent.

---

## 3. Стеллажи — ПЕРЕРИСОВАТЬ КРУПНЕЕ И БЛИЖЕ

Текущие стеллажи выглядят как одинаковые тонкие шкафы на дальнем плане. Они должны стать главным игровым полем.

Нужен модуль, который можно повторять кодом.

### Основной модуль
`assets/environment-v2/shelf-bay-large.png`

Canvas: **420×620 px**, transparent.

Требования:
- металлический супермаркет/склад стеллаж;
- 4 заметные полки;
- глубина полки читается;
- боковые стойки толще текущих;
- чуть перспективы/света;
- зона каждой полки достаточно чистая для наложения товаров кодом;
- без встроенных товаров;
- без текста;
- без ценников с цифрами;
- можно оставить маленькие пустые жёлтые ценники/держатели как декоративный элемент;
- края не должны быть слишком тёмными.

### Верхняя категория
`assets/environment-v2/shelf-header-large.png`

Canvas: **420×84 px**, transparent.

- массивная верхняя плашка;
- без текста;
- код сам поставит название категории;
- стилистика должна совпадать со shelf-bay-large.

### Нижняя база / foreground connection
`assets/environment-v2/shelf-base-shadow.png`

Canvas: **420×100 px**, transparent.

- тень под стеллажом;
- лёгкий контакт с полом;
- нужна, чтобы модуль не выглядел «наклеенным».

## 4. Передний план сцены

Сейчас между полками и игроком слишком много пустого пола. Нужно дать сцене foreground-глубину.

Создать:

`assets/environment-v2/foreground-floor-strip.png`

Размер: **1600×260 px**, transparent/partial alpha.

Содержимое:
- лёгкая перспектива пола;
- мягкие тени;
- несколько ненавязчивых складских деталей по краям: коробка, угол поддона, тень, линия разметки;
- центральная зона должна быть свободной для персонажа и тележки;
- НИКАКИХ надписей;
- НИКАКИХ крупных объектов по центру;
- не превращать в отдельный фон — это только foreground overlay.

---

## 5. Визуальный масштаб в итоговой сцене

Целевой canvas игры: **1600×900**.

Примерные production размеры после интеграции:
- персонаж: 250–300 px высотой;
- тележка: 360–430 px шириной;
- стеллаж: 300–350 px шириной каждый;
- видимых стеллажей одновременно: 3–4, не 5 узких;
- персонаж и тележка располагаются перед полками и частично перекрывают нижнюю часть стеллажей;
- полки начинаются визуально ближе к игроку;
- нижний foreground занимает примерно 25–30% высоты экрана.

Главный критерий: если сделать screenshot без UI, сцена всё равно должна выглядеть как полноценная игра.

---

## 6. Анимационные требования

Никакой сложной покадровой анимации не требуется.

Нужно только, чтобы мы могли кодом собрать:
- idle: 2 кадра, 500–700 ms;
- walk: 4 кадра, 90–120 ms на кадр;
- pick: 3 кадра, короткая последовательность 250–400 ms;
- cart: 2 кадра / короткий feedback после добавления товара.

Фреймы должны иметь одинаковый canvas и baseline.

## 7. Что НЕ делать

Не переделывать:
- товарные PNG Batch 01;
- order-panel;
- phone-frame;
- кнопки;
- иконки HUD;
- warehouse-backdrop — пока оставляем существующий фон.

Не добавлять:
- текст внутри графики;
- логотипы реальных брендов;
- персонажей покупателей;
- дополнительные UI-панели;
- декоративные вывески;
- полный новый gameplay mockup вместо production-assets.

## 9. Acceptance criteria

Batch 02 принимается только если:
- персонаж визуально не меньше 250 px по высоте в preview;
- тележка выглядит как полноценный игровой объект, а не иконка;
- персонаж и тележка находятся в foreground перед полками;
- стеллажи выглядят ближе и крупнее текущих;
- screenshot без UI всё равно читается как игровая сцена;
- товары остаются заметными и не теряются на полках;
- все PNG с прозрачностью там, где она требуется;
- размеры файлов соответствуют ТЗ;
- анимационные кадры совпадают по baseline.

После Batch 02 дизайнер НЕ переходит к новым товарам и другим ассетам без отдельного подтверждения.
