# ТЗ ДИЗАЙНЕРУ — «Собери заказ!» / Batch 01

## Задача

Подготовить первый production-набор графики для web-игры «Собери заказ!».

Это НЕ просьба нарисовать красивый скриншот целиком. Нужны отдельные игровые ассеты, которые разработчик сможет точно разместить в Phaser.

Перед работой прочитать:
1. `docs/GAME_BRIEF.md`
2. `docs/WIREFRAME.md`
3. `docs/ART_BIBLE.md`
4. `docs/ASSET_MANIFEST.md`

## Визуальный ориентир

Современный чистый pixel-art / pixel-inspired стиль:
- яркие и хорошо читаемые товары;
- тёмно-синий UI;
- тёплое складское освещение;
- аккуратный коммерческий casual-game look;
- не старый 8-bit и не грязный ретро-пиксель.

Главная эмоция: «приятно быстро собирать заказы».

## Критически важно

- не использовать реальные бренды, логотипы маркетплейсов и торговых сетей;
- не делать декоративные надписи на фоне;
- не добавлять записки, кружки, коробки с текстом, слоганы и случайные вывески;
- не рисовать товары прямо в стеллаж;
- не собирать UI в одну огромную картинку;
- не менять композицию основного экрана;
- все production-ассеты сдавать отдельными PNG.

## Что нужно нарисовать сейчас

Только `Batch 01` из `docs/ASSET_MANIFEST.md`:

### Окружение
- пустая секция стеллажа;
- header секции;
- tileable нижняя часть пола.

### Персонаж
- worker idle;
- worker pick/scan;
- пустая тележка.

### UI
- левая панель заказа;
- корпус телефона;
- primary button: normal / hover / pressed;
- иконки star / money / clock / pause.

### Тестовые товары — 12 штук
- milk carton;
- banana;
- toilet paper;
- dumplings;
- kefir;
- apple;
- chocolate;
- dish soap;
- rice;
- frozen berries;
- shampoo;
- batteries.

Точные размеры и пути файлов указаны в `docs/ASSET_MANIFEST.md`.

## Как сдавать

Структура:

```text
assets/
  environment/
  character/
  ui/
  products/
```

PNG, прозрачный фон там, где требуется.

Дополнительно сделать `preview-batch-01.png` размером `1600×900`: собрать из этих ассетов пример gameplay-композиции по `WIREFRAME.md`.

Важно: preview нужен только для визуальной проверки. Разработчик будет использовать отдельные production PNG, а не резать preview.

## Требования к товарам

Каждый товар — `64×64`.

Проверка качества:
- узнаётся без подписи;
- не касается краёв canvas;
- визуальный масштаб согласован со всеми остальными;
- один источник света;
- хорошая читаемость на тёмной полке;
- силуэты отличаются;
- нет реальных торговых марок.

## Требования к UI

UI должен выглядеть как часть игры, а не как сайт или административная панель.

Не использовать сложный мелкий декор. Главные элементы должны переживать масштабирование до 1366×768.

В панелях не вшивать динамический текст, цифры, рейтинг, названия товаров и отзывы. Всё это выводит игра.

## Что НЕ делать в Batch 01

- полный набор 36–48 товаров;
- меню;
- loading screen;
- магазин улучшений;
- дополнительные локации;
- десятки анимаций персонажа;
- рекламные баннеры;
- логотип игры;
- мобильный portrait UI.

Сначала мы интегрируем Batch 01 в игру и проверяем стиль в живом Phaser-экране. Только после этого будет разрешён Batch 02.

## Критерий приёмки

Batch 01 считается успешным, если после прямой интеграции без ручного «дорисовывания» и изменения layout игровой экран начинает визуально приближаться к утверждённому концепту, а все 12 товаров легко различаются в реальном игровом масштабе.
