# ART BIBLE — «Собери заказ!»

## Цель

Сделать prototype визуально близким к утверждённому концепту, но не превращать production в рисование огромного количества уникальных сцен.

Ключ: современная, чистая, насыщенная pixel-art / pixel-inspired графика с хорошей читаемостью интерфейса и товаров.

## Базовый формат

- reference resolution: `1600×900`;
- landscape-first;
- integer-friendly scaling для pixel assets;
- UI может быть чуть менее «жёстко пиксельным», чем игровой мир, но должен визуально совпадать с ним;
- не использовать реальный логотип/айдентику маркетплейсов, сетей и брендов продуктов.

## Визуальная формула

`уютный современный склад + яркие товары + тёмно-синий game UI + тёплый свет + чистые пиксельные формы`

Не делать грязный ретро-8-bit. Нужен аккуратный современный pixel-art уровня коммерческой казуальной игры.

## Палитра

Окружение:
- тёмно-синие/серо-синие металлические стеллажи;
- нейтральный бетон/тёплый складской свет;
- фон темнее gameplay-товаров.

UI:
- основной фон панелей: глубокий navy;
- светлый текст;
- зелёный — успешное действие/деньги;
- золотой — рейтинг/звёзды/достижения;
- красный — штраф/ошибка;
- голубой — прогресс/XP.

Товары должны иметь собственные яркие цвета и хорошо отличаться друг от друга на расстоянии.

## Контраст и читаемость

Главный приоритет — игрок должен мгновенно отличать товары.

Запрещено:
- одинаковые силуэты у большинства товаров;
- мелкие нечитаемые этикетки как основной способ различения;
- слишком похожие оттенки соседних товаров;
- визуальный шум на фоне;
- декоративный текст на коробках, кружках, записках и стенах.

Допустимо использовать короткие псевдо-бренды/символы на упаковке, только если они помогают отличать предметы. Они не должны копировать реальные торговые марки.

## Товары

Production master для одиночного товара: `64×64 px`, прозрачный PNG.

Внутри master:
- предмет занимает примерно 52–58 px по максимальной стороне;
- 2–4 px воздуха по краям;
- фронтальный или лёгкий 3/4 ракурс;
- единый свет сверху/слева;
- чёткий силуэт;
- минимальная, но выразительная тень/объём;
- без собственного фона.

Категории:
1. молочные;
2. овощи/фрукты;
3. бакалея;
4. снеки/сладкое;
5. бытовая химия;
6. заморозка/прочее.

Внутри одной категории товары родственны по визуальному языку, но не должны сливаться.

## Стеллаж

Стеллаж — модульный production asset.

Не рисовать один огромный фон со всеми товарами внутри.

Нужны отдельные элементы:
- shelf bay / секция стеллажа;
- верхняя табличка категории;
- горизонтальная полка;
- фон ячейки;
- ценник/малый декоративный маркер без читаемого текста.

Игра сама размещает товары поверх полки.

## Персонаж и тележка

Персонаж — визуальный feedback, не объект управления.

Нужны только состояния, которые реально видит игрок:
- idle;
- берёт товар / scan;
- кладёт товар в тележку;
- короткая success reaction.

Можно реализовать 2–4 кадровые циклы. Не нужен полный locomotion set.

Тележка:
- один основной asset;
- отдельное состояние/overlay для наполнения можно делать программно через мини-иконки товаров.

## UI

UI должен быть production-ready и собираться из отдельных компонентов, не из одной картинки.

Нужны:
- panel frame;
- order row;
- primary button;
- secondary button;
- progress bar frame/fill;
- star icons;
- money/rating/clock/pause icons;
- phone frame;
- result/review card;
- badge/rank plate;
- category tab.

Все кнопки должны иметь минимум состояния `normal`, `hover`, `pressed`; disabled — если действительно используется.

## Телефон

Телефон — важный эмоциональный объект и должен выглядеть как отдельный интерфейс внутри интерфейса.

Он показывает:
- последний отзыв;
- деньги/штраф;
- звёзды;
- рейтинг;
- ранг/XP;
- кнопку следующего заказа.

Не перегружать телефон нижним меню, если оно не участвует в v1.

## FX

Большая часть juice делается программно, поэтому отдельной графики минимум.

Нужны маленькие универсальные элементы:
- sparkle;
- success star;
- coin/ruble pop;
- red warning/penalty mark;
- scan flash.

## Критерий качества

Production batch принимается только если:
1. товары хорошо читаются в реальном размере;
2. стиль всех ассетов единый;
3. UI не выглядит как generic dashboard;
4. окружение поддерживает игру, а не отвлекает;
5. после интеграции экран визуально движется к утверждённому концепту без необходимости «додумывать» композицию программистом.
