# DECISIONS

Журнал продуктовых и технических решений, чтобы не переобсуждать уже зафиксированное.

## 2026-09-14

### D-001 — основной движок

Используем Phaser 4 вместо универсального Godot-подхода для этой web-first 2D игры.

Причина: быстрее управлять точной 2D-геометрией, UI, browser SDK и data-driven контентом; меньше разрыв между дизайном и реализацией.

### D-002 — стек

Phaser 4.2.1 + Vite + TypeScript. React не используется.

### D-003 — производственный формат

Проект должен быть реализуем за один рабочий день и давать около 1–2 часов основной карьеры.

### D-004 — графика

Pixel-art / pixel-inspired production style для снижения стоимости ассетов и повышения визуальной консистентности.

### D-005 — игра

Рабочее название: «Собери заказ!».

Фантазия: игрок работает сборщиком заказов и проходит карьеру от стажёра до сборщика №1.

### D-006 — core loop

`заказ → выбор товаров → замены/ошибки → отправка → деньги/отзыв/штраф → рейтинг/ранг → новый заказ`.

Игрок может взять товар, которого нет в заказе. Итог оценивается после отправки.

### D-007 — основной UX

Не делать WASD/свободное перемещение персонажа. Основное взаимодействие — мышь/touch по товарам на стеллаже. Персонаж и тележка используются как визуальная часть и feedback.

### D-008 — визуальный экран

Зафиксировано направление концепта:

- слева заказ;
- центр стеллажи;
- сверху ранг/таймер/деньги/рейтинг;
- справа телефон с отзывом и карьерными показателями;
- минимум декоративного текста в окружении.

### D-009 — управление проектом

Пользователь выступает руководителем. Агент самостоятельно принимает обычные продуктовые, технические, UX и контентные решения и обращается к руководителю только по существенным изменениям продукта.

### D-010 — контрольные точки руководителя

Руководитель подключается не для повседневного производства, а только когда нужен его реальный ресурс: дизайнер/визуальное согласование, проверка живой сборки, запуск кода/скриптов/SDK на его стороне, доступы к площадкам или существенное продуктовое/релизное решение.
